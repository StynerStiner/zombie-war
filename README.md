# ZOMBIE WAR

**built by William** — a 2D top-down arcade survival game made with Python and Pygame.

You are walking through a dangerous rainforest while zombies rain out of the sky.
You start with **no weapon**. Find a glowing weapon box, get a **random** weapon,
and score as high as you can — but every weapon disappears after **3 kills**.

No gore, no downloads: every graphic is drawn with Pygame shapes and every sound
is generated in code, so the game works on any computer with Python + Pygame.

---

## 1. Folder structure

Save every file inside one folder called `ZombieWar`:

```text
ZombieWar/
├── main.py            ← START HERE: game loop, all six screens, HUD, collisions
├── settings.py        ← all constants: screen size, colours, weapon + zombie stats
├── player.py          ← Player class (movement, health, carrying a weapon)
├── zombie.py          ← Zombie class (falls from the sky → lands → chases → attacks)
├── weapon.py          ← Weapon and Projectile classes + random_weapon()
├── weapon_box.py      ← WeaponBox class (the glowing crates)
├── score_manager.py   ← ScoreManager class (high score + score history in JSON)
├── effects.py         ← particles, dust, floating score numbers, shock rings, glows
├── environment.py     ← rainforest background: trees, plants, rocks, fog, puddles
├── audio.py           ← synthesized music and sound effects (no audio files needed)
├── scores.json        ← your saved high score and last scores (created automatically)
├── requirements.txt   ← the single dependency: pygame
├── README.md          ← this file
├── build_web.py       ← OPTIONAL: builds the browser version (see section 7)
├── assets/
│   ├── README.txt     ← explains the OPTIONAL art/audio you may drop in later
│   └── sounds/        ← optional .wav overrides (empty by default — not required)
├── web_build/         ← generated by build_web.py (safe to delete)
└── zombie-war-web/    ← generated static site for Vercel (safe to delete)
```

All `.py` files live **directly inside `ZombieWar/`** (not in sub-folders), because
they import each other by name (`from player import Player`). `scores.json` sits
next to `main.py`. Only `assets/` is a sub-folder, and it is optional.

## 2. Install Pygame

Open the terminal (in VS Code: **Terminal → New Terminal**) and run:

```bash
python3 -m pip install pygame
```

On Windows use:

```bash
py -m pip install pygame
```

Or install from the requirements file:

```bash
python3 -m pip install -r requirements.txt
```

> A ready-made virtual environment is already included in this folder as `.venv`
> (Pygame 2.6.1 installed). To use it instead, run `./.venv/bin/python main.py`,
> or in VS Code press `Cmd+Shift+P` → **Python: Select Interpreter** → pick the
> one inside `ZombieWar/.venv`. You can delete `.venv` if you prefer a plain
> system install — the two commands above are all you need.

## 3. Run the game

```bash
cd path/to/ZombieWar        # wherever you keep the folder
python3 main.py
```

On Windows: `py main.py`

### In VS Code

1. **File → Open Folder…** and choose the `ZombieWar` folder.
2. Open `main.py`.
3. Press the ▶ **Run** button (top right), or press `F5`, or run `python3 main.py`
   in the integrated terminal.

### Check everything works without opening a window

```bash
python3 main.py --selftest
```

This runs the whole game headlessly and verifies all six screens render, all six
weapons fire, all seven zombie types fall and land, scoring is correct, the
3-kill rule fires, weapon boxes hand out random weapons, bullets kill zombies,
game over saves the score, and restart works.

## 4. Controls

| Key | Action |
| --- | --- |
| `W` `A` `S` `D` or arrow keys | Walk (up, down, left, right) |
| Mouse | Aim |
| `Spacebar` or left mouse button | Shoot |
| `P` | Pause / resume |
| `R` | Restart (on the game-over screen) |
| `M` | Mute / unmute sound |
| `Esc` | Back to the menu (quit from the title screen) |
| `I` / `H` | Instructions / score history (from the title screen) |
| `-` / `=` | Turn the sound down / up |

The controls are also listed on the opening menu and the pause screen.

### On a phone or tablet

The game detects touch automatically and shows on-screen controls:

| Touch | Action |
| --- | --- |
| Drag on the **left** half | Walk (a thumb-stick appears wherever your thumb lands) |
| Hold the **FIRE** button (bottom right) | Shoot — it aims at the nearest zombie for you |
| Hold anywhere else on the **right** half | Aim and shoot at that exact spot |
| Tap the **II** button (top right) | Pause |
| Tap a menu button, or tap anywhere on the title screen | Start / choose |

Both halves work at once, so you can walk and shoot at the same time.

### Your teammate

**BUDDY** fights alongside you: he follows you around, shoots the nearest
zombie on his own, and his kills score points for the team **without** using up
any of your three weapon charges. If he takes too much damage he is downed,
and he picks himself back up next to you a few seconds later.

### Which one am I?

You are the character in the **blue jacket with the orange cap**, standing in a
glowing blue ring with a **YOU** label above your head. While you have no
weapon, an orange arrow next to you points at the nearest weapon box and shows
how far away it is.

## 5. How the game works

**Weapons** — you begin unarmed. Weapon boxes appear at random spots and glow
gold. Touch one and the game **randomly** picks one of six weapons for you; you
can never choose. The weapon's name is shown in the score panel and pops up on
screen when you get it.

| Weapon | Damage | Ammo | Notes |
| --- | --- | --- | --- |
| Pistol | 26 | 60 | Reliable, steady damage |
| Shotgun | 20 ×6 pellets | 30 | Devastating up close |
| Assault Rifle | 17 | 150 | Full auto — hold to spray |
| Crossbow | 85 | 22 | Pierces through zombies |
| Flamethrower | 8 | 260 | Short range wall of fire, pierces |
| Energy Blaster | 45 | 48 | Piercing plasma bolts |

After **3 kills** your weapon disappears and the screen shows
*"Weapon expired! Find another weapon box."* The 3-kill counter restarts every
time you pick up a new weapon. Running out of ammo also ends the weapon.

**Zombies** — every zombie shows its point value floating above its head:

| Zombie | Points | Mark |
| --- | --- | --- |
| Regular | 10 | — |
| Fast | 20 | — |
| Strong | 30 | — |
| Giant | 50 | — |
| **Gold marked** | **100** | glowing ⭐ star |
| **Red marked** | **200** | glowing 👑 crown |
| **Purple marked** | **300** | glowing ◆ diamond |

The three marked zombies appear occasionally from wave 2 onward and glow so you
can spot them in a crowd.

**Difficulty** — a new wave starts every 24 seconds. Each wave spawns zombies
faster, allows more of them on screen at once, and makes them quicker and
tougher.

**Score panel** (always visible at the top): current score, high score, zombies
killed, current weapon, ammo, kills remaining before the weapon disappears,
player health, wave, and time survived.

## 6. Saved scores

`scores.json` is written next to `main.py` and holds:

```json
{
  "high_score": 7420,
  "games_played": 14,
  "history": [ { "score": 7420, "kills": 61, "wave": 7, "date": "2026-07-26 12:40" } ]
}
```

The last **20** runs are stored; the game-over screen shows the most recent **10**
(newest at the top), and the Score History screen shows more. The file is written
atomically, so a crash can never corrupt it. If the file is missing or damaged the
game simply starts a fresh one instead of crashing.

To wipe your scores, delete `scores.json` (or set its contents to
`{"high_score": 0, "games_played": 0, "history": []}`).

## 7. Playing in a browser (the Vercel version)

Live: **[zombie-war-web.vercel.app](https://zombie-war-web.vercel.app)**

Pygame cannot run on Vercel directly — Vercel only serves static files and
short-lived serverless functions, and a Pygame game needs a real window and a
long-running process. The browser version is therefore compiled to
**WebAssembly** with [pygbag](https://pypi.org/project/pygbag/), which produces
a static site that any host can serve.

Rebuild and redeploy after changing the game:

```bash
python3 -m pip install pygbag           # one time
python3 build_web.py                    # writes ./zombie-war-web/
cd zombie-war-web && vercel deploy --prod
```

`build_web.py` copies the game into `web_build/zombiewar/`, runs pygbag, and
leaves a ready-to-upload site in `zombie-war-web/` (about 122 KB: `index.html`,
`zombiewar.apk`, `zombiewar.tar.gz`, `favicon.png`). The desktop game is never
modified by the build.

### How the web version differs from the desktop one

| | Desktop | Browser |
| --- | --- | --- |
| First start | instant | slow — it downloads Python 3.12 + pygame-ce (~1.5 MB) from the pygame-web CDN, so allow up to a minute the first time; later visits are cached |
| Sound | plays immediately | starts only after you click the "start" splash (browsers block audio until you interact) |
| Saved scores | `scores.json` next to the game | the browser's `localStorage`, so scores are per-browser and separate from the desktop ones |
| Fonts | your system monospace font | a bundled fallback font — text is slightly wider/narrower in places |

Two notes about the code that make the browser build possible, both harmless on
the desktop: the game loop in `main.py` is an `async` coroutine that awaits
`asyncio.sleep(0)` every frame (a blocking `while` loop would freeze the browser
tab), and `score_manager.py` detects `sys.platform == "emscripten"` and switches
to `localStorage`.

**If the deployed link asks visitors to log in**, the project has Vercel
Deployment Protection switched on. Turn it off in the Vercel dashboard:
*Project → Settings → Deployment Protection → Vercel Authentication →
Disabled*, then redeploy.

## 8. Troubleshooting

### `ModuleNotFoundError: No module named 'pygame'`

Pygame is installed for a different Python than the one running the game. Use
the same interpreter for both:
`python3 -m pip install pygame` then `python3 main.py`.
In VS Code, check the interpreter shown in the bottom-right status bar.

### No sound

The game generates its own audio; if your machine has no working audio device it
silently disables sound and keeps playing. Press `M` to check the mute toggle.

### The window is too big for my screen

Open `settings.py` and change `SCREEN_WIDTH` / `SCREEN_HEIGHT` (for example 1024
and 600). Everything scales off those two values.

### It feels too hard / too easy

Everything is tunable in `settings.py`: `PLAYER_MAX_HEALTH`, `KILLS_PER_WEAPON`,
`WAVE_DURATION`, `SPAWN_INTERVAL_START`, `SPEED_BONUS_PER_WAVE`, and the
`WEAPONS` / `ZOMBIE_TYPES` tables.
